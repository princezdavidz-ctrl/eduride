# Edu Ride Vehicle Controller — Electrical Schematic Design

**Status:** Design specification / schematic capture plan — not released for fabrication  
**Repository:** `PCB_Project/`  
**Target board:** 100 mm × 80 mm, 2-layer prototype  
**Main controller:** ESP32-S3-WROOM-1-N16R8  
**Vehicle input:** 12 V / 24 V nominal

## 1. Design overview

The controller is installed in a school bus. It acquires GNSS position, reports location and pickup events to the Edu Ride backend over cellular data, and presents the driver's route / pickup workflow on a separately powered HDMI touchscreen controller.

Functional blocks:

1. Vehicle power input, fuse, reverse-polarity protection and transient suppression.
2. Wide-input vehicle-to-5 V regulator and 3.3 V logic regulator.
3. ESP32-S3-WROOM-1-N16R8 controller, reset / boot and USB programming.
4. SIM7600G-H cellular modem interface with a dedicated high-current 5 V supply.
5. External GNSS module interface.
6. Display-controller UART / control interface. HDMI is handled by the external display controller, never by the ESP32.
7. microSD storage, external RTC I²C connector, driver buttons, status LEDs and buzzer.
8. Protected connectors, test points and a common signal-ground reference.

## 2. Critical review of the current KiCad project

The existing `PCB_Project/PCB_Project.kicad_sch` contains an input-protection fragment and references `untitled.kicad_sch`. The referenced `untitled.kicad_sch` currently contains an LM2596S-ADJ buck fragment and references an empty `DC Converter.kicad_sch`.

**Do not connect the existing LM2596S-ADJ stage directly to a vehicle 12/24 V input.** Its 40 V maximum input rating does not provide the transient margin needed for a vehicle electrical system. Replace this stage with an automotive-suitable wide-input regulator architecture selected against the actual transient envelope. A TVS diode alone does not establish load-dump compliance.

The present files do not yet constitute a complete ESP32 / modem / GNSS / display controller schematic. This document defines the intended circuit and the capture checklist; it does not claim ERC/DRC or automotive qualification.

## 3. Power architecture

### 3.1 Vehicle input (12 V / 24 V)

Recommended functional sequence:

`J1 VEHICLE_IN (+BATT, GND) → F1 input fuse → reverse-polarity MOSFET stage → surge / load-dump clamp → wide-input buck → +5V_SYS`

- Use a connector and fuse rated for the installation current, wire gauge and fault-clearing requirements.
- Select a high-side reverse-polarity controller / MOSFET arrangement with a drain-source rating and transient SOA appropriate to the validated vehicle profile. Do not use a small 30 V P-channel MOSFET on the vehicle rail.
- Select the TVS / surge clamp only after checking the maximum continuous charging voltage, clamping voltage at the expected pulse current, pulse energy, wiring impedance and regulator absolute maximum. Verify ISO 7637-2 and ISO 16750-2 test profiles required by the target vehicle.
- Use an automotive-rated buck regulator with sufficient input rating after clamping, thermal margin, and current capacity for the board's 5 V loads. Final IC, inductor, diode / synchronous FET, compensation and input/output capacitors must follow the chosen manufacturer's reference design.
- Add reverse battery, jump-start, cranking, load-dump, EFT and ESD analysis to the validation plan. Do not represent this prototype as automotive-qualified until tested.

### 3.2 Logic rails

- `+5V_SYS`: generated by the protected vehicle-input buck.
- `+3V3`: regulated from +5V_SYS for ESP32, SD card, GNSS logic and low-voltage peripherals.
- Place local decoupling at every module supply pin group; add bulk capacitance at the modem connector and the 5 V power entry as dictated by measured load steps.
- The SIM7600G-H must have its own supply path sized for the selected carrier board's peak current. Use a dedicated regulated 5 V source / power module with at least 3 A transient capability as a design starting point; confirm the exact carrier's input range, peak current, connector and thermal needs from its datasheet.
- Do not power the modem from the ESP32 3.3 V rail.
- The HDMI touchscreen and its controller are separately powered. Provide signal ground and UART/control connections only; do not route HDMI signals through the ESP32 board.

## 4. Controller and interface allocation

Use the exact ESP32-S3-WROOM-1-N16R8 module variant and its official module footprint / pinout. The following is a proposed GPIO allocation to be checked against the selected module datasheet, board routing and all boot / strapping constraints before schematic ERC.

| Function | ESP32-S3 GPIO | Interface / notes |
|---|---:|---|
| USB D- / D+ | GPIO19 / GPIO20 | Native USB; route as a controlled differential pair, add ESD protection at connector |
| GNSS RX / TX | GPIO17 / GPIO18 | UART; confirm module voltage levels |
| Modem RX / TX | GPIO15 / GPIO16 | UART via level translation if the selected modem carrier is not 3.3 V tolerant |
| Display controller RX / TX | GPIO8 / GPIO9 | UART; separate controller handles HDMI video and touch |
| RTC SDA / SCL | GPIO10 / GPIO11 | I²C; pull-ups to the correct logic rail; external RTC module connector |
| microSD SCK / MOSI / MISO / CS | GPIO4 / GPIO5 / GPIO6 / GPIO7 | SPI; 3.3 V card interface, local decoupling and ESD protection |
| Pickup / next-stop / menu buttons | GPIO1 / GPIO2 / GPIO3 | Active-low to GND with pull-ups; debounce in firmware or RC where needed |
| GPS / network / status LEDs | GPIO38 / GPIO39 / GPIO40 | Use series resistors; confirm LED current and GPIO drive |
| Buzzer enable | GPIO41 | Drive transistor / MOSFET; do not drive a high-current buzzer directly |
| Reset / boot | EN / GPIO0 | Follow Espressif reference circuit; expose reset and boot access |

**Pin-allocation warning:** GPIO35–GPIO37 are reserved for octal PSRAM / flash use on the N16R8 configuration and are intentionally not assigned. Verify every pin against the official N16R8 module datasheet before freezing the design. Do not treat this proposed table as a substitute for pinout review.

## 5. Required schematic sheets

### Sheet A — Vehicle input and power
- J1 vehicle input connector, polarity markings and chassis / signal-ground strategy.
- F1 fuse near the connector.
- Reverse-polarity protection controller and suitably rated MOSFETs.
- Automotive transient / load-dump clamp and input filtering.
- Wide-input 5 V buck with full manufacturer reference circuit.
- +3V3 regulator, enable / power-good where available, decoupling and test points.
- Clearly label `VBAT_PROTECTED`, `+5V_SYS`, `+3V3`, `GND`.

### Sheet B — ESP32-S3 controller and USB
- ESP32-S3-WROOM-1-N16R8 with correct footprint and exposed antenna keepout.
- EN pull-up / reset circuit and GPIO0 boot access.
- Required module decoupling and local bulk capacitance.
- USB-C receptacle, CC1 / CC2 Rd resistors for a USB 2.0 device, D+ / D- routing, ESD protection and VBUS sensing / protection as appropriate.
- UART / debug header and labelled test points.
- Do not connect USB VBUS directly to the vehicle rail.

### Sheet C — Cellular modem and GNSS
- SIM7600G-H carrier connector with VBAT / 5V input, GND, UART TX/RX, optional PWRKEY, RESET and status pins as supported by the exact carrier.
- Dedicated modem power connector / regulator and bulk capacitance close to the connector.
- UART level translation if the selected carrier's UART is 1.8 V. Raw 1.8 V SIM7600 UART must not be connected directly to 3.3 V ESP32 GPIO.
- External GNSS connector with power, GND, UART RX/TX and optional PPS / antenna bias only where supported by the selected module.
- Keep GNSS RF / antenna routing away from the modem switching regulator and high-speed digital edges.

### Sheet D — Driver display and controls
- Display-controller connector: UART TX/RX, GND, optional reset / wake / status and separately supplied power only if explicitly designed for pass-through.
- No HDMI pins or HDMI video routing to the ESP32.
- Three driver controls: PICKUP CONFIRM, NEXT STOP, MENU / BACK.
- Pull-ups, ESD / transient protection at external button harnesses as required.
- Buzzer transistor driver with flyback protection if the buzzer is inductive.
- GPS / cellular / system LEDs with calculated resistors.

### Sheet E — Storage and RTC
- microSD socket in 3.3 V SPI mode, correct card-detect / write-protect handling if present, series damping resistors where needed, local decoupling and ESD protection.
- External RTC I²C connector: 3V3, GND, SDA, SCL. Add I²C pull-ups only once it is confirmed the RTC module does not already contain pull-ups; avoid parallel pull-ups that make the effective resistance too low.
- Optional battery backup is on the RTC module, not assumed to be present on the main board.

## 6. Connector pinout proposal

Connector pin order must be printed on the PCB silkscreen and documented in the assembly drawing.

- `J1 VEHICLE_IN`: 1 = +BATT (12/24 V), 2 = GND.
- `J_MODEM`: 1 = modem supply input (per selected carrier), 2 = GND, 3 = ESP TX → modem RX (translated if required), 4 = modem TX → ESP RX (translated if required), 5 = PWRKEY (optional), 6 = RESET (optional), 7 = STATUS (optional).
- `J_GNSS`: 1 = module supply (per GNSS datasheet), 2 = GND, 3 = ESP TX → GNSS RX, 4 = GNSS TX → ESP RX, 5 = PPS (optional).
- `J_DISPLAY`: 1 = GND, 2 = 3V3 logic reference, 3 = ESP TX → display RX, 4 = display TX → ESP RX, 5 = RESET / WAKE (optional), 6 = STATUS (optional). Display power is external unless a verified current budget permits otherwise.
- `J_RTC`: 1 = 3V3, 2 = GND, 3 = SDA, 4 = SCL.
- `J_DEBUG`: GND, 3V3 reference, UART TX, UART RX, EN, BOOT.
- Buttons: one side to GND, other side to assigned GPIO; use keyed harness connectors.

Connector pinout is a design proposal. Confirm the exact mating carrier/module pinout before assigning footprints or manufacturing cables.

## 7. Layout and PCB constraints

- Board target: 100 × 80 mm; perform actual placement / mechanical fit before claiming it fits.
- 2-layer FR-4 is acceptable for an initial prototype only if return paths, modem current, thermal dissipation and RF clearances are demonstrated.
- Keep the cellular modem and its antenna / RF connector at a board edge with antenna keepout per module guidance.
- Keep GNSS antenna away from modem antenna, switching nodes, buck inductor and digital clocks.
- Use short, wide power paths for modem supply and vehicle input. Calculate copper width from current, copper weight, allowable temperature rise and connector limits.
- Keep buck switch node compact and away from GNSS / UART / RF.
- Route USB D+ / D- as a controlled differential pair with continuous reference plane and ESD protection close to the connector.
- Use a continuous ground reference plane; avoid splitting return paths under high-speed signals.
- Add test points for VBAT_PROTECTED, +5V_SYS, +3V3, GND, modem supply, EN, BOOT, UARTs and I²C.

## 8. Verification gates before fabrication

1. Verify exact module / carrier datasheets and all pin numbers, footprints and voltage levels.
2. Replace the existing 40 V LM2596 vehicle-input stage with a suitable automotive wide-input design.
3. Complete all five schematic sheets and hierarchical labels.
4. Run KiCad ERC; resolve every error and document intentional no-connects.
5. Assign verified footprints and confirm connector mating compatibility.
6. Run PCB DRC, clearance, copper-width, thermal and antenna keepout checks.
7. Review BOM availability, lifecycle, ratings and second sources.
8. Validate power sequencing and modem current bursts on the bench.
9. Test vehicle transients against the required ISO 7637-2 / ISO 16750-2 profile with appropriate protection and test equipment.
10. Only then generate Gerbers, drill files, BOM and pick-and-place outputs.
